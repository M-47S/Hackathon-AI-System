
# EnergyTool AI Service

**ИИ-консультант для B2B-клиентов EnergyTool.**
Сервис на FastAPI, который принимает историю диалога, находит релевантные фрагменты в базе знаний (RAG), генерирует ответ с помощью LLM и возвращает строго типизированный JSON для интеграции с Go-бэкендом.

---

## 🏗 Архитектура и поток данных

```text
[Frontend] <--> [Go Backend] <--(HTTP/JSON)--> [AI Service (FastAPI)]
                                                   |
                                        +----------+----------+
                                        |                     |
                                   [RAG Pipeline]       [LLM Client]
                                   (FAISS + Chunker)   (GigaChat/OpenAI)
                                        |                     |
                                   [Knowledge Base]      [External API]
```

1. **Go Backend** передаёт текущее сообщение, историю, профиль клиента и резюме.
2. **AI Service** достаёт контекст из FAISS (векторный поиск + реранкер).
3. **LLM** генерирует ответ, используя Structured Outputs (Pydantic).
4. **AI Service** валидирует `product_ids`, мёржит профиль (чтобы не затереть старые данные) и возвращает ответ бэкенду.

## 📂 Структура проекта

### 1. `API/` — Точка входа и бизнес-логика

* **`main.py`** — FastAPI приложение. Содержит `lifespan` для предзагрузки тяжёлых моделей (эмбеддер, реранкер) и авто-сборки RAG-индекса, если его нет. Эндпоинты: `GET /health`, `POST /v1/chat`.
* **`config.py`** — Загрузчик переменных окружения (`.env`). Определяет пути к моделям, настройки RAG и LLM.
* **`schemas.py`** — Pydantic-модели. **Важно:** имена полей синхронизированы с Go-структурами напарников (`object_count` вместо `objects_count`, `recommended_product_ids` вместо `product_ids`).
* **`service.py`** — `ChatService`. Ядро логики: retrieval -> вызов LLM -> пост-обработка. Отвечает за валидацию продуктов, слияние профиля и fallback-ответы при ошибках LLM.
* **`prompts.py`** — Системный промпт консультанта (правила выбора `action`, извлечения профиля, тональность).
* **`products.py`** — Статичный каталог продуктов EnergyTool. Используется для вставки в промпт и для валидации `recommended_product_ids`.

### 2. `RAG/` — Поиск по базе знаний

* **`pipelines.py`** — Слой поиска. Реализует логику `Small-to-Big` (поиск по листьям, передача родительских чанков в LLM), TOC-фильтрацию (отсев оглавлений) и гибридный поиск.
* **`Chunking/`** — Чанкер на базе `llama_index`. Режет Markdown по заголовкам (H1-H3), создаёт иерархию чанков.
* **`Embedding/`** — Обёртка над `multilingual-e5-large`. Генерирует векторы для FAISS.
* **`Ranking/`** — Реранкер на базе `bge-reranker-v2-m3`. Переранжирует топ-кандидатов, отсекая нерелевантные.
* **`Store/`** — `DocumentStore` (хранит чанки и метаданные) и `VectorStore` (FAISS-индекс).

### 3. `LLM/` — Интеграция с языковой моделью

* **`Client.py`** — OpenAI-совместимый клиент. Поддерживает `response_format` (Structured Outputs), автоматически ретраит 429 ошибки и пересоздаёт пул соединений.
* **`auth.py`** — Провайдеры токенов. `GigaChatTokenProvider` умеет обновлять OAuth-токен Сбера каждые 30 минут. `StaticTokenProvider` используется для Gemini/OpenAI.
* **`structs.py`** — Датаклассы для запросов и ответов LLM.

### 4. `evaluation/` — Локальный грейдер

Скрипты для офлайн-оценки качества ответов по методике МТС (MatchRate, WinRate). Использует LLM-судью и сравнивает ответы с baseline.

## ⚙️ Переменные окружения (`.env`)

Сервис читает единый файл `API/.env`. Скопируй `API/.env.example` в `API/.env` и заполни.

### LLM (Обязательно)

| Переменная | Описание                                                                              | Пример                 |
| -------------------- | --------------------------------------------------------------------------------------------- | ---------------------------- |
| `AI_AUTH_KEY`      | **Обязательно.** Auth Key от GigaChat (или API Key от OpenAI/Gemini). | `MDE5...`                  |
| `AI_BASE_URL`      | Адрес API.                                                                               | `https://api.giga.chat/v1` |
| `AI_MODEL`         | Название модели.                                                                | `GigaChat-2-MAX`           |
| `AI_SCOPE`         | Scope для OAuth GigaChat.                                                                  | `GIGACHAT_API_PERS`        |

### RAG и пути к моделям

| Переменная  | Описание                                                                                                | Дефолт                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| `RAG_KB_DIR`        | Путь к папке с `.md` файлами базы знаний.                                         | `./RAG/Store/_test_/Data Knowledge` |
| `RAG_INDEX_DIR`     | Куда сохранять FAISS-индекс.                                                                 | `./RAG/Store/Storage`               |
| `RAG_AUTO_BUILD`    | Если `true`, сервис сам соберёт индекс при старте, если его нет. | `true`                              |
| `RAG_TOP_K`         | Сколько чанков передавать в LLM.                                                        | `5`                                 |
| `RAG_RERANK`        | Включить/выключить реранкер.                                                           | `true`                              |
| `RAG_CHUNK_SIZE`    | Размер чанка в токенах (для сборки).                                                | `640`                               |
| `RAG_CHUNK_OVERLAP` | Перекрытие чанков в токенах.                                                            | `64`                                |

### Модели (Эмбеддер и Реранкер)

| Переменная     | Описание                                                                          | Дефолт                  |
| ------------------------ | ----------------------------------------------------------------------------------------- | ----------------------------- |
| `EMBEDDING_MODEL_NAME` | Путь или имя HF-модели эмбеддера.                                | `.../multilingual-e5-large` |
| `EMBEDDING_DEVICE`     | `cpu` или `cuda`.                                                                  | `cpu`                       |
| `EMBEDDING_BATCH_SIZE` | Размер батча при сборке индекса (ускоряет старт). | `32`                        |
| `RERANKER_MODEL_PATH`  | Путь к модели реранкера.                                              | `.../bge-reranker-v2-m3`    |
| `RERANKER_DEVICE`      | `cpu` или `cuda`.                                                                  | `cpu`                       |
| `RERANKER_MAX_LENGTH`  | Максимальная длина контекста для реранкера.         | `1024`                      |

## 🚀 Быстрый старт

### 1. Подготовка

```bash
cd ai-service
python -m venv venv
source venv/bin/activate  # или venv\Scripts\activate на Windows
pip install -r requirements.txt
```

### 2. Настройка окружения

```bash
cp API/.env.example API/.env
# Открой API/.env и впиши AI_AUTH_KEY
```

### 3. Запуск сервиса

*(При первом запуске сервис сам соберёт FAISS-индекс из базы знаний — это займёт 1–3 минуты в зависимости от CPU. В логах будет прогресс `[embed] batch #N`).*

```bash
python -m uvicorn API.main:app --host 0.0.0.0 --port 8001
```

### 4. Проверка работы

Открой Swagger UI: **http://localhost:8001/docs**

- Вызови `POST /v1/chat` с тестовым JSON.
- Проверь `GET /health` (должен вернуть `{"status": "ok"}`).

## 📡 Контракт API (`POST /v1/chat`)

**Request (от Go Backend):**

```json
{
  "session_id": "s1",
  "request_id": "r1",
  "message": "У нас 50 магазинов, собираем показания вручную",
  "history": [],
  "customer_profile": {
    "business_type": "retail",
    "object_count": 50,
    "problem": "Высокие расходы",
    "metering_method": "manual"
  },
  "conversation_summary": null
}
```

**Response (в Go Backend):**

```json
{
  "session_id": "s1",
  "action": "recommend",
  "answer": "Для сети из 50 магазинов подходит Облачная АСКУЭ...",
  "recommended_product_ids": ["cloud_askue"],
  "customer_profile": {
    "business_type": "retail",
    "object_count": 50,
    "problem": "Высокие расходы",
    "metering_method": "manual"
  },
  "conversation_summary": "Сеть из 50 магазинов..."
}
```

### Особенности работы `action`

* `recommend` — возвращает `recommended_product_ids`, которые **всегда** валидируются по каталогу `API/products.py`. Если LLM вернула несуществующий ID, `action` автоматически меняется на `ask_question`.
* `ask_question` — в поле `answer` гарантированно будет знак вопроса `?`.
* `out_of_scope` — если вопрос вне темы EnergyTool или в RAG не нашлось фактов.
* `customer_profile` — всегда возвращается полным снимком. Если LLM вернула `null` для известного ранее поля, сервис сохранит старое значение (merge-логика).

## 🛠 Диагностика и логирование

В `API/main.py` реализовано пошаговое логирование старта `[1]...[5]` с обходом буферизации `uvicorn` (через `print(..., flush=True)`).

* Если сборка индекса занимает слишком много времени, `faulthandler` через 90 секунд выведет стектрейс всех потоков, чтобы понять, на каком этапе зависла система.
* Все ошибки LLM (429, таймауты) автоматически ретраятся внутри `LLM/Client.py` с экспоненциальной задержкой (от 3 до 12 секунд).
* Если RAG-индекс отсутствует, сервис автоматически соберёт его при старте (если `RAG_AUTO_BUILD=true`). Напарникам не нужно запускать отдельные скрипты.
